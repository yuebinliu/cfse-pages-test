总览技术栈优点

优点详解

不是功能清单，是"为什么这么设计"。

1 · 静态与动态各就各位

单页是静态快照（读 R2，毫秒级），列表页是实时查询（读 D1，永远最新）。 新文章不需要重建整站 —— 这与传统静态生成器最大的区别。

2 · 自愈，而不是全站 404

单页在 R2 未命中时，Worker 会现场从 D1 渲染并写回 R2。清空存储、换模板、迁移路径都不会让站点整体挂掉， 最差是某篇文章首次访问慢几百毫秒。

3 · 双后台，互为镜像

熟悉的 WordPress 后台负责写作与媒体；Worker 后台负责模板/风格、批量运维、日志。 两侧数据可双向对齐（按远端 ID 记录，幂等，不重复建文）。

4 · 面向 Markdown 工作流

Obsidian 这类编辑器可以直接发布：标题/正文/别名/分类标签都通过 WP REST 形状交互， 图片自动上传并回填 source_url；原稿按 md 保留，因此永远不会被富文本编辑器重排。

5 · 多托管，一份产物多处分发

对象存储

S3 兼容协议一次覆盖 R2 / B2 / Wasabi / MinIO / OSS / COS。

本地目录

零联网落盘，用于打包分发或纯静态站。

你的 Worker

走 /upload，顺带写库、清缓存。

git 型托管

GitHub Pages 等：一次 commit = 一次部署，天然增量。

6 · 免费额度内可跑

Workers 10 万请求/天、D1 500 万行读/天、R2 10GB + 出站免费、KV 10 万读/天。 静态资源走 assets 不计费；动态页只在缓存 MISS 时回源 ⇒ 日 PV 十万级仍在安全区。

7 · 中文/非 ASCII 路径不踩坑

存储 key = 中文原文，读写在同一个函数里规范，URL 返回时逐段编码。 （这一条是踩过坑之后固化的：签名、编码、key 形态三者必须一致。）

8 · 主题与内容解耦

风格包 = 6 类模板（单页壳/列表条目/首页/分类/标签/归档）+ 资源，可多套保存、一键应用、历史回退； 应用后可一键重建全部单页。

9 · 幂等与去重

媒体以「内容 SHA-256 前 8 位 + 原名」命名 ⇒ 同一张图重复发布会命中同一 key，不堆积副本； D1 写入是真 upsert（ON CONFLICT(wp_id) DO UPDATE）。

10 · 可以只当 CMS 用

不装 WordPress 插件也能跑：Worker 侧自带核心建表与初始化向导， 所以「纯 Worker CMS + 任意静态托管」是一条独立的产品线。
